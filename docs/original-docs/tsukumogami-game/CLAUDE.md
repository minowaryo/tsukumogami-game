## オーナーについて

- Ryo。マニラ在住の日本人。IT業界約10年（開発・テスト→要件定義・業務分析）、MBA保有
- **ゲーム開発は初めて**。絵は描けない。3Dの経験もなし。36歳
- **活かせる強み**：
  - 開発・テストの経験 → AIが書いたコードを読み、おかしな点に気づける（AI時代の個人開発で最も効く力）
  - 要件定義・業務分析の経験 → 「何を作るか」を整理・言語化する力＝企画書・仕様づくり
  - MBA → 市場の見方、収益設計、撤退ラインの判断
  - → Claude Code は Ryo を「コードを書く人」ではなく「**判断し、レビューし、仕様を決める人**」として扱うとよい
- 本業がある副業プロジェクト。目安は**週10〜15時間**。他の副業構想よりこのゲームを優先する
- Key 作品（CLANNAD、AIR など）が大好きな「鍵っ子」。全体を貫く物語の軸に強い関心
- 遊んできたゲーム（参考にしやすい）：ウマ娘、ブルーアーカイブ、アークナイツ、FEヒーローズ、DQタクト、DQライバルズ、State of Survival、Random Dice、Pokémon GO、クイズ！黒猫、パラノマサイト（ホラー）、焚き火（癒やし系）。昔はギャルゲー・恋愛ゲーム世代。ホラー好き
- やりとりは**日本語**。専門用語は短く補足する

## 作業の進め方（Claude Code へのお願い）

1. **小さく作って、すぐ触れる形で見せる。** 大きな設計書より、動くものを優先
2. **決定事項と提案を区別する。** Ryo が決めたことは `docs/05_decisions.md` に追記。Claude の提案は「案」と明記
3. **AI生成の画像・音声は「試作用」として扱う。** ファイル名やフォルダで区別（例：`assets/proto/`）。最終素材は人間のイラストレーター・声優に依頼する方針
4. **外部への投稿・ストア申請・課金設定は Claude が実行しない。** 公開系の操作は必ず Ryo が手動で行う
5. **キャラは全員、ひと目で大人に見えるデザインにする**（結婚エンドがあるため。海外ストア審査対策）
6. 実在の薬物・自傷などは題材にしない。不気味さは架空・ファンタジー表現で出す
