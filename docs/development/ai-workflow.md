## 役割分担（要約）

| | 内容 |
|---|---|
| **Ryo** | 何を作るか（判断A）、それで良いか（判断B）、取り込み（判断C）。お金・外部公開・新しいツール・正典・権利の判断。外部への投稿・申請は自分の手で |
| **AI** | 調査、ブレスト、ドキュメント・ADR の下書き、実装、テスト、画像生成と QC、動作確認、記録（`docs/decisions.md`、`PLAN.md`） |

## Claude Code の使い方

```
1. 調べる      … docs/ai-context/、PLAN.md、関係する原案とドキュメントを読む
2. 判断A       … 作るもの・完了条件・やらないこと・手間と費用を出し、OK をもらう
3. 作る        … 合意した範囲で実装する。ロジックはテストを先に書く（30-testing.md）
4. 確かめる    … 実際に動かして、完了条件を満たすか確認する
5. 判断B       … 触って・見て判断できるものを出す
6. 判断C       … コミット・マージの案を出す（70-git.md）
```

### 毎回読むもの

- `docs/ai-context/project-summary.md`
- `docs/ai-context/glossary.md`
- `docs/development/roles-and-decisions.md`
- `PLAN.md`

## Codex の使い方

`AGENTS.md` に同じ役割分担を英語で書いてある。Codex にも判断A・B・C と止まる条件を守らせる。

## 禁止

- 判断A の前の実装
- 止まる条件に当たったのに聞かずに進める
- 実行して確かめずに「できた」と報告する
- 秘密情報をプロンプトに含める

## 道具を先に使う

ルールや作業ごとに、次の順で考え、残った判断だけを AI が担う。

1. **道具で確かめられるか**：文章のルールより、毎回走るチェック（テスト、自動 QC、YAML の検証）を優先する
2. **道具で直せるか**：整形などの機械的な修正は道具に任せる
3. **道具で場所を探せるか**：道具に作業リストを作らせ、AI は1件ずつ直し、チェックで確かめる
