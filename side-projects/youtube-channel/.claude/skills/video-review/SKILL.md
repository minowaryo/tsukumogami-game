# video-review — 動画のレビュー（YouTube サイドプロジェクト）

基準は **`side-projects/youtube-channel/guidelines/guardrails.md` だけ**に書いてある。このスキルは手順だけを持つ。
基準を変えたいときは guardrails.md を直し、このファイルに基準を書き写さない。

## 最初に読む

1. `side-projects/youtube-channel/guidelines/guardrails.md`（全部）
2. レビューする対象（`ideas/` のカード・企画書、`scripts/` の台本、書き出した動画の仕様と字幕）
3. 比べる相手が要るとき：`ideas/video-ideas.md` の一覧

## モード

依頼の言葉から選ぶ。はっきりしないときは対象の状態から決める（カードだけ → 企画、台本がある → 台本、動画がある → 公開前）。

| モード | 対象 | 使う基準（guardrails.md） |
|---|---|---|
| **ネタ選び** | 複数のアイデア | 5-1 の関門＋採点表を各ネタに当て、順位を付ける |
| **企画** | 1 つのアイデア・企画書 | 5-1、4（R1〜R9）、採点表 |
| **台本** | 台本 | 5-2（削除テスト・置き換えテスト・場所の指摘）、4、採点表 |
| **公開前** | 書き出した動画 | 5-3、4 |

## 手順

1. **越えてはいけない線（R1〜R9）を先に見る**。1 つでも当たれば、点数に関係なく「直す」。当たった行・時刻を示す
2. **採点表で 0〜2 点を付ける**。各点に「なぜその点か」を 1 文で書く。根拠は対象の中の行・時刻で示す
3. **台本モードでは削除テストと置き換えテストを実際に行う**：J・M の行を抜き出して消したと仮定し、結論が成り立つかを書く。一般的な解説チャンネルの台本と比べて何が残るかを書く
4. **判定を出す**：進める／直して進める／保留（Ryo の材料待ち）／やめる。基準は guardrails.md の目安の点数
5. **直す点は「どこを・どう」まで書く**。抽象的な指摘（「もっと独自性を」）で終わらせない
6. **Ryo に聞くことを書く**：特に M（実体験）が足りないとき、どんな場面が欲しいかを具体的に聞く

## 守ること

- **M（実体験）を AI が作らない、点を付けない**。Ryo が書いた体験だけを M として数える。AI が埋めた「例の場面」は 0 点（R9）
- **作者とレビューする人を分ける**：台本を書いたのと同じ流れでレビューすると、自分の案に甘くなる。
  台本・公開前のモードは、できればサブエージェント（新しい文脈）に対象と guardrails.md だけを渡して行う。結論や作者の意図は渡さない
- **事実の真偽はこのスキルで決めない**：出典が要る主張を一覧にするまで（R4）。確かめるのは別の作業
- レビューは提案。進めるかどうかを決めるのは Ryo

## 出力

レビューした対象のファイルに「レビュー」の節を足す（なければ作る）。チャットには判定と直す点の要約だけを出す。

```markdown
## レビュー（<モード>、<YYYY-MM-DD>、<誰が：AI / サブエージェント>）

**判定**：進める／直して進める／保留／やめる

| 項目 | 点 | 理由（根拠の行・時刻） |
|---|---|---|
| 独自の解釈（I） | | |
| 実体験（M） | | |
| 専門性（E） | | |
| 型の使い方 | | |
| 自分ごと度 | | |
| パッケージ | | |
| **合計** | **/12** | |

越えてはいけない線：当たりなし／R? — <場所と直し方>

直す点：
1. <どこを> → <どう>

Ryo に聞くこと：
- <具体的な場面の問い>
```

ネタ選びのモードでは、上の表を 1 行 1 ネタの比較表にまとめ、順位と理由（季節・制作の手間・チャンネルの芯との近さ）を付ける。
あわせて、**地域のバランス**（guardrails.md 2-4）を確かめる：選んだネタを足したときに、直近の本数で PH の割合が上限を超えないか。
超えるなら、PH 以外の重心のネタを繰り上げるか、PH のネタを Shorts に回す案を出す。

企画・台本のモードでも、2-4 の「動画 1 本ごとのルール」（日本とフィリピン以外の比較相手が 1 つ以上）を確かめる。
